# 프런트엔드 품질 보강 (2026-11-10)

## 범위와 결정

예약 목록의 취소 성공 후 포커스와 기존 독립 리뷰에서 남긴 지연 응답 회귀 테스트를 보강했다. 기존 Vue·Vitest 구조를 사용하며 라이브러리·백엔드·API 계약·CI는 변경하지 않았다. 브라우저 검증은 사용자 요청으로 제외했다.

취소 성공 시 확인 버튼이 사라지므로 성공 안내를 `tabindex=-1`로 프로그램 방식 포커스 대상으로 삼는다. Vue DOM 반영 후 화면이 유지 중인 경우에만 이동하고, 그 뒤 목록을 갱신한다. 안내는 조회 중·성공·실패에도 유지되어 늦은 조회 완료가 다시 포커스를 빼앗지 않는다. 화면 이탈 시 포커스나 후속 GET을 실행하지 않는다.

## 회귀 테스트와 검증

- 취소 성공 후 목록 조회 성공·실패 모두 성공 안내로 포커스를 옮기는 테스트 2개를 먼저 추가했다. 수정 전 두 테스트가 본문 포커스를 관찰해 실패했고 수정 후 통과했다.
- 기존 코드의 방어를 검증하는 지연 응답 테스트 17개를 추가했다. AbortSignal을 무시하고 뒤늦게 resolve/reject하는 Promise를 사용한다.
- 공간 목록: 새 요청 뒤 이전 성공·실패, 화면 이탈 뒤 성공·실패를 무시한다.
- 공간 등록·상세: 등록 중 이탈 뒤 성공·실패가 재이동·오류를 남기지 않고, 상세 경로 변경 뒤 늦은 실패와 이탈 뒤 성공·실패가 상태를 덮어쓰지 않는다.
- 예약 생성: 사전선택 query 변경·이탈 뒤 성공·실패와 생성 POST의 query 변경·이탈 뒤 성공·실패가 선택·결과·오류를 덮어쓰지 않는다. 기존 이전 요청 확인 안내를 유지한다.

`frontend/`에서 `npm run test:unit` 전체 116개(기존 97 + 신규 19), `npm run lint`, `npm run build`가 종료 코드 0이다. build는 vue-tsc 타입 검사를 포함한다. 이 테스트는 API 모킹·DOM 환경의 검증이며 실제 브라우저의 키보드 조작을 검증한 것이 아니다.

기존 화면별 문서의 초기 테스트 수·리뷰 기록은 당시 결과로 보존하고, 완료한 후속 항목은 이 문서로 연결했다. architecture.md의 목록·취소 후속 문구와 시간 입력 설명, 생성 실패 시 Swagger 목록 안내를 현재 화면에 맞게 수정했다.

## 독립 리뷰와 남은 작업

Superpowers requesting-code-review의 독립 리뷰어 Subagent가 origin/main·HEAD `2d01abe` 대비 실제 미커밋 diff와 신규 문서를 요구사항·관련 뷰와 대조했다. Critical 0·Important 0·Minor 0이다. 포커스 이동 순서와 이탈 방어, 지연 응답 테스트의 단언 및 문서 일관성을 확인했다. 리뷰어는 git diff --check를 실행했고 테스트·lint·build는 재실행하지 않았다. 추가 수정 지적이 없어 중복 리뷰하지 않았다. 실제 브라우저·E2E, 실제 API 재검증, 백엔드 전체 테스트와 원격 CI는 이번 범위에서 실행하지 않았다. 기존 개발 의존성 audit 항목은 별도 확인이 필요하다. 커밋·push는 하지 않았다.
