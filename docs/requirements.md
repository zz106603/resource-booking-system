# MVP 요구사항

## 목적과 상태

공유 공간 예약 서비스를 완성하면서 Codex 작업 지침, 자동 검증, 실패 복구 및 Context 관리 방법을 실제 작업에 맞춰 점진적으로 개선한다. 백엔드 포트폴리오로 활용할 수 있도록 비즈니스 규칙과 통합·동시성 테스트의 근거를 남긴다.

이 문서는 초기 구현 기준안이다. 아래의 초안 정책은 작성자가 제안한 기본값이며, 구현 전에 확인할 사항은 `architecture.md`에 별도로 기록한다. 현재 기본 애플리케이션과 PostgreSQL 환경 통합 테스트만 구성했으며, 아래 도메인 기능과 수용 기준은 아직 구현·검증되지 않았다.

## MVP 기능

| ID | 기능 | 범위 |
| --- | --- | --- |
| F1 | 공간 등록 | 이름, 설명, 수용 인원을 입력해 예약 가능한 공간을 등록한다. |
| F2 | 공간 조회 | 공간 목록과 개별 공간 상세를 조회한다. |
| F3 | 예약 생성 | 공간, 예약자 표시명, 시작·종료 시각으로 예약한다. |
| F4 | 예약 취소 | 예약 ID로 취소하며 이력은 보존한다. |
| F5 | 예약 목록 | 공간별 예약 목록을 조회하고 상태 및 시간 구간으로 필터링한다. |
| F6 | 입력 검증·예외 처리 | 잘못된 입력, 없는 자원, 중복 예약을 일관된 오류 응답으로 구분한다. |
| F7 | 검증 | 실제 PostgreSQL 기반 통합 테스트와 동시 예약 테스트로 핵심 규칙을 검증한다. |

## 핵심 비즈니스 규칙

- 공간 이름은 공백만으로 구성할 수 없고 수용 인원은 양의 정수다. 이름의 유일성은 요구하지 않는다.
- 예약은 존재하는 공간에 대해서만 생성한다. 예약자 표시명은 필수이며 인증된 사용자 신원을 의미하지 않는다.
- 예약 시작은 종료보다 빨라야 하고, 생성 시 시작은 서버가 판단한 현재 시각보다 미래여야 한다.
- 시각은 UTC 오프셋이 포함된 입력을 받아 동일한 순간을 기준으로 비교한다. 저장·비교는 UTC 기준이며 표시 시간대는 별도 관심사다.
- 예약 구간은 `[시작, 종료)`다. 기존 예약 종료와 신규 예약 시작이 같으면 허용한다.
- 같은 공간에서 취소되지 않은 예약 A, B가 `A.start < B.end && B.start < A.end`를 만족하면 중복이다. 포함 관계와 완전히 같은 구간도 중복이다.
- 중복 방지는 동시 요청에서도 성립해야 한다. 서로 다른 공간의 예약은 영향을 주지 않는다.
- 상태는 `CONFIRMED`와 `CANCELLED`다. 생성 성공 시 확정되고 취소 후 복구하지 않는다. 취소 예약은 시간 점유에서 제외한다.
- 초안 정책으로 확정 예약은 시작 전만 취소할 수 있으며, 시작 시각에 도달했거나 지난 확정 예약의 취소는 409로 처리한다. 이미 취소한 예약의 재취소는 시작 시각 경과 여부와 관계없이 200으로 처리하며 상태를 유지한다.
- 생성 실패 시 예약을 남기지 않는다. 취소 실패 시 기존 상태를 유지한다.

## 검증 가능한 수용 기준

아래 HTTP 상태는 초기 API 계약 제안이다. 구체적인 URL·필드·페이징 계약은 구현 전 확정한다.

| ID | 조건과 행동 | 기대 결과 |
| --- | --- | --- |
| AC1 | 유효한 이름과 양의 수용 인원으로 공간 등록 | 201, 생성 ID 반환, 목록·상세에 동일한 값이 조회됨 |
| AC2 | 빈 이름 또는 0 이하 수용 인원으로 등록 | 400, 필드 오류 반환, 공간 미생성 |
| AC3 | 없는 공간 상세 조회 또는 해당 공간 예약 생성 | 404, 예약 미생성 |
| AC4 | 유효한 미래 구간으로 빈 공간 예약 | 201, `CONFIRMED` 상태 및 입력과 같은 순간의 시각 반환 |
| AC5 | 시작 ≥ 종료, 시작 ≤ 현재, 잘못된 시각 형식 또는 빈 예약자 표시명 | 400, 예약 미생성; 현재 시각은 고정 Clock으로 경계 검증 |
| AC6 | 동일 공간에 부분 겹침·포함·동일 구간 요청 | 각각 409, 기존 확정 예약만 유지 |
| AC7 | 기존 예약의 종료와 시작이 맞닿는 예약 또는 다른 공간의 같은 시간 예약 | 201 |
| AC8 | 시작 전 확정 예약 취소 후 같은 구간 재예약 | 취소 200 및 `CANCELLED` 유지, 재예약 201 |
| AC9 | 취소 예약 재취소(시작 시각 전·동일·경과 모두 포함) / 없는 예약 취소 / 시작 시각에 도달했거나 지난 확정 예약 취소 | 각각 200 / 404 / 409, 기존 데이터 일관성 유지 |
| AC10 | 공간·상태·조회 구간을 지정한 예약 목록 조회 | 조건에 맞는 예약만 반환; 구간은 동일한 겹침 규칙 적용, 시작 시각·ID 오름차순 |
| AC11 | 독립 트랜잭션에서 같은 공간·동일 미래 구간으로 N개 동시 생성(N ≥ 2) | 정확히 1개 성공, 나머지 중복 충돌, DB 확정 예약 1개; 여러 번 반복해 검증 |
| AC12 | 잘못된 입력·없는 자원·충돌·예상하지 못한 내부 실패 | 각각 400·404·409·500, 공통 오류 코드·메시지 제공; 스택 추적과 내부 DB 정보 미노출 |

AC11은 별도 DB 연결과 동시 출발 장치를 사용하고 모든 작업 완료 후 DB 상태를 확인한다. 순차 호출이나 단일 테스트 트랜잭션으로 동시성 검증을 대신하지 않는다. 통합 테스트는 Testcontainers PostgreSQL을 사용하며 H2 결과로 대체하지 않는다.

## MVP 제외 기능

- 로그인, 회원 관리, 역할·권한 및 예약 소유자 검증
- 반복 예약, 대기열, 승인, 결제, 알림, 외부 캘린더 연동
- 예약 시간 변경, 공간 수정·삭제, 운영시간·휴일·장비별 정책
- 다중 테넌트, 분산 서비스, 캐시, 메시지 브로커
- React 화면 구현, 배포 환경과 고가용성 구성

인증 없이 예약 ID로 취소하는 범위는 학습용 MVP 전제다. 외부 공개 운영에 앞서 인증·권한 정책을 별도로 설계한다.
