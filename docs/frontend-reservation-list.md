# 예약 목록·취소 화면

## 범위와 계약

[실행 안내](frontend-setup.md)에 따라 실행하고 상단 예약 목록 또는 `/reservations`로 접속한다. 예약 생성 완료 화면에서도 목록으로 이동할 수 있다. 백엔드는 [목록 API](reservation-list.md)와 [취소 API](reservation-api.md)를 그대로 사용한다.

- 공간·상태 미지정은 파라미터를 생략한다. 공간 선택은 별도 20개 페이지로 조회하며 페이지를 바꿔도 선택을 유지한다. 표에서는 공간 ID와 상세 링크를 제공한다.
- 날짜와 00:00~24:00의 30분 단위 시간을 입력한다. Asia/Seoul 기준이며 24:00은 다음 날 00:00이다. 시작·종료를 함께 지정하거나 모두 비우며 과거도 조회한다. 시작 < 종료를 검증하고 `+09:00`을 URL 인코딩해 전송한다. 구간은 겹침 조회이며 맞닿기만 하는 예약은 제외한다.
- 입력 중 필터와 적용 필터를 분리한다. 적용·초기화는 첫 페이지로 이동한다. 페이지는 0부터·20개 고정, 시작 시각·ID 오름차순이다. 취소 후 같은 조건·페이지를 갱신하며 사라진 마지막 페이지는 유효한 마지막 페이지로 한 번 보정한다.
- 상태·예약자·시작/종료·취소 시각을 표시한다. 모든 시각 표시는 Asia/Seoul이고 로딩·빈 결과·조회 오류·재시도를 구분한다. 좁은 화면의 표는 가로 스크롤을 사용한다.
- 취소는 예약 ID·공간·예약자·시간을 확인한 뒤 명시적으로 확정한다. 처리 중 중복 제출과 필터·페이지 조작을 막으며 POST를 자동 재시도하지 않는다. CONFIRMED이면서 시작 전인 행에만 취소 버튼을 활성화하지만 최종 판단은 서버가 한다.
- 이미 시작된 예약 409, 없는 예약 404, 일시적 오류 503과 통신 오류를 안내한다. 통신이 끊기면 목록으로 결과를 확인한다. 취소 성공 후 조회 실패는 취소 실패로 표시하지 않고 성공 안내와 조회 재시도를 함께 제공한다. 취소된 예약의 재취소 200은 API 계약으로 유지한다.
- 새 조회·화면 이탈 시 이전 GET을 중단하고 늦은 응답을 무시한다. 화면 이탈 후 취소 응답은 목록 상태를 갱신하지 않는다. 인증·소유자 권한·예약 변경·백엔드·CI 변경은 이번 범위에 없다.

## 검증 (2026-11-10)

`frontend/`에서 `npm run lint`, `npm run test:unit`, `npm run build`가 종료 코드 0이다. 전체 테스트 97개(기존 69 + 목록·취소 API 9 + 화면 19)가 통과했다. build는 `vue-tsc --build` 타입 검사를 포함한다. 기존 예약 생성의 공유 시간 함수 변경도 전체 테스트 범위에 포함했다.

최초 RED는 새 모듈·화면 부재로 테스트 파일 2개 로드 실패였고, 구현 후 통과했다. 추가한 키보드 확인 테스트에서 제목 포커스 누락을 재현한 뒤 확인 영역 제목으로 이동·돌아가기 시 원래 버튼으로 복귀하도록 수정해 통과했다. 404·409·503, 중복 취소, 성공 후 조회 실패, 필터 초기화·부분 입력·과거 조회·페이지 보정·공간 선택 유지·지연 GET 무시를 모킹으로 검증했다.

실제 HTTP는 기존 개발 DB와 분리한 PostgreSQL 17.11(`list_check`, 15433), local 백엔드(18080), 별도 Vite 프록시(5174)로 확인했다. `backend/`의 `.\gradlew.bat bootJar --no-daemon`은 성공(up-to-date)했다. 기존 5173 Vite는 그대로 유지했고, 검증용 Vite만 프로그램 방식의 `createServer`로 API 프록시를 18080에 지정했다.

- local 샘플 공간 4개와 API로 만든 예약 21개의 page0=20·page1=1·전체21·2페이지를 확인했다.
- 공간·CONFIRMED·서울 오프셋 구간의 조합 필터가 맞닿는 다음 예약을 제외하고 1건을 반환했다.
- 취소·재취소 200과 동일 cancelledAt, 이후 CANCELLED=1·CONFIRMED=20을 확인했다. 없는 예약 취소는 404였다.
- 격리 DB에 과거 CONFIRMED 예약을 준비하고 취소 시 409 RESERVATION_ALREADY_STARTED를 확인했다. `/reservations` HTML은 200이었다.
- 검증용 Java·Vite·`--rm` PostgreSQL을 종료하고 18080·5174·15433 리스너와 컨테이너가 없음을 확인했다. 기존 5173(PID 23964)은 유지했다.

이 HTTP 검증은 브라우저 렌더링·클릭을 검증한 것이 아니다. 이전 브라우저 정책 차단과 사용자 지시에 따라 브라우저 도구는 재시도하지 않았다. 실제 키보드·포커스·반응형·E2E 및 원격 CI는 미검증이다. 백엔드 소스는 바꾸지 않았으며 이번에는 백엔드 전체 테스트·고부하 벤치마크·Trivy를 재실행하지 않았다.

## 독립 리뷰와 남은 항목

Superpowers requesting-code-review의 독립 리뷰어 Subagent가 기준 origin/main·HEAD `a02dcb6` 대비 실제 미커밋 변경과 신규 소스·테스트를 요구사항·API 문서와 대조했다. Critical 0·Important 0·Minor 1이다. Minor는 취소 성공 후 확인 영역과 목록이 다시 생성될 때 결과 안내 등으로 키보드 포커스를 옮기는 개선이다. 취소 전 확인 제목·돌아가기 포커스는 구현했으며 성공 후 복원은 당시 후속으로 남겼고 이후 [품질 보강](frontend-quality.md)에서 성공 안내로 포커스를 옮기도록 수정했다. 중요한 수정이 없어 중복 리뷰하지 않았다. 리뷰어는 diff 검사를 실행했으며 테스트·빌드·실제 HTTP를 재실행하지 않았다.

성공 후 포커스 개선과 지연 응답 회귀 테스트의 최신 검증은 [frontend-quality.md](frontend-quality.md)를 따른다. 브라우저 검증과 기존 개발 의존성 audit 항목이 남아 있다. 커밋·push는 하지 않았다.
