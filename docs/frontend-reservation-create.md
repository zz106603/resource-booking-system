# 예약 생성 화면

## 범위와 실행

[프런트엔드 실행 안내](frontend-setup.md)에 따라 서버를 실행하고 상단 예약 생성 링크 또는 `/reservations/new`를 사용한다. 공간 상세의 예약 링크는 `?spaceId=실제ID`를 전달한다. [예약 API 계약](reservation-api.md)을 사용하며 예약 목록·취소 화면·인증·백엔드 변경은 포함하지 않는다.

공간은 기존 API로 20개씩 조회해 선택한다. 페이지를 이동해도 선택은 유지하며 선택된 공간이 현재 페이지 밖이면 별도 옵션으로 표시한다. 상세에서 진입한 공간은 개별 조회하므로 첫 페이지 밖 ID도 선택할 수 있다. 조회 중·빈 공간·조회 오류/재시도·없는 사전선택 공간을 안내한다. 등록된 공간이 없으면 local 샘플 또는 공간 등록 기능을 사용한다.

## 입력과 결과 계약

- 예약자명 필수·100자, 공간은 양의 안전 정수 ID다. 입력 문자열을 임의로 trim하지 않는다.
- 날짜와 시간을 분리해 입력한다. 시간 선택지는 오전/오후 구분 없이 00:00~24:00의 30분 간격이다. 24:00은 선택 날짜의 다음 날 00:00으로 정규화한다. 화면에 Asia/Seoul(UTC+09:00)을 명시하고 브라우저 시스템 시간대에 의존하지 않도록 `YYYY-MM-DDTHH:mm:00+09:00`으로 전송한다. 날짜 라이브러리는 추가하지 않았다. API 정밀도는 유지하고 화면 선택지만 제한한다.
- 실제 달력 날짜·미래 시작·시작<종료를 제출 때 확인한다. 종료와 다른 예약의 시작이 같으면 허용되는 `[시작, 종료)` 계약이다. 클라이언트 시각과 서버 시각이 다르거나 요청 대기 중 시작이 지나면 서버가 거부할 수 있으며 최종 판단은 서버다.
- RESERVATION_CONFLICT/409는 다른 시간·공간을 선택하도록 안내하고 입력을 보존한다. 서버 fieldErrors는 필드별로, 시간 비즈니스 오류는 전체 메시지로 표시한다. 404 공간 없음·503·네트워크 오류도 구분한다.
- 공간·날짜 변경 시 예약 목록 API에서 CONFIRMED와 겹침 구간 필터로 예약 현황을 조회한다. 100개씩 모든 페이지를 읽으며 취소 예약은 제외한다. 24:00 시작 선택의 다음 날 30분 구간까지 포함한다. 시작은 해당 30분 구간, 종료는 선택한 시작부터 종료까지 전체 구간이 예약과 겹치면 비활성화한다. 맞닿는 구간은 허용한다.
- 예약 현황 조회 중·실패 시 시간 선택과 제출을 막고 새로고침을 제공한다. 새 현황에서 이미 선택한 시간이 예약됐으면 해당 시간 선택을 해제해 안내한다. 409 시 현황을 다시 조회하지만 POST를 자동 재시도하지 않는다. 결과는 조회 시점의 참고 정보이며 동시 예약의 최종 정합성은 서버 배타 제약이 보장한다. 화면 이탈·날짜 변경 시 이전 조회를 취소하고 늦은 결과를 반영하지 않는다.
- 제출 중 폼과 버튼을 비활성화하고 중복 제출을 막는다. POST 자동 재시도는 없다. 응답이 끊기면 Swagger 목록으로 생성 여부를 확인한다. 화면을 떠나도 서버 처리가 취소되지는 않는다.
- 성공하면 예약 번호·선택 공간·예약자·서울 기준 시작/종료를 같은 화면에 표시한다. 새 예약 입력 버튼으로 명시적으로 새 폼을 연다. 이 결과는 페이지 새로고침 후 보존하지 않으며 예약 단건 조회 화면을 의미하지 않는다.

코드는 `src/api/reservations.ts`와 `ReservationCreateView.vue`에 두고 기존 fetch·ApiError·공간 API와 CSS를 재사용한다. Router와 진입 링크 외 기존 기능·의존성·CI를 변경하지 않는다.

## 독립 리뷰와 남은 항목

위 57개 테스트·빌드·독립 리뷰는 최초 분 단위 입력 구현의 기록이다. 이후 30분 간격·24시간제 선택 UI와 확정 예약 기반 선택 비활성화 변경 당시에는 사용자 지시에 따라 검증을 실행하지 않았다. 이후 PR #11의 CI 실패를 확인하고 사용자 요청으로 아래 CI 수정 검증을 수행했다.

Superpowers requesting-code-review의 독립 리뷰어 Subagent가 origin/main·HEAD `e894239` 대비 실제 diff·신규 파일·요구사항·백엔드 계약을 읽기 전용으로 대조했다. Critical 0·Important 0·Minor 1건이다. Minor는 query 변경·화면 이탈 후 사전선택 GET/생성 POST의 늦은 성공·실패가 최신 상태를 덮어쓰지 않는 회귀 테스트 보강이다. active/selectionRequest 방어는 코드상 적절하며 동작 결함은 발견하지 못했다. 후속 테스트 보강으로 남기고 중요한 코드 수정이 없어 중복 리뷰하지 않았다. 리뷰어는 테스트·빌드·실제 HTTP 검증을 재실행하지 않았다.

브라우저 렌더링·클릭·날짜 선택기·키보드·반응형·E2E·Trivy는 미검증이다. 이전 브라우저 정책 차단과 사용자 지시에 따라 브라우저 도구를 호출하지 않았다. 이후 [예약 목록·취소 화면](frontend-reservation-list.md)을 구현했다. 위 회귀 테스트 보강과 기존 개발 의존성 audit 항목은 후속이다.

## PR #11 Frontend CI 실패 수정 (2026-11-10)

[실패 run 42749321549](https://github.com/zz106603/resource-booking-system/actions/runs/42749321549)의 job 129608926932에서 설치·lint·타입 검사는 성공했고 Unit and component tests의 7개 실패로 build가 건너뛰어졌다. 로컬도 57개 중 7개 실패·50개 통과로 재현했다.

원인은 CI 환경이 아니라 테스트와 현재 UI 계약의 불일치다. 기존 테스트가 제거된 #startAt/#endAt을 찾았고, 공간·날짜 선택 후 예약 현황 조회가 끝나야 제출할 수 있는 새 조건과 조회 모킹도 반영하지 않았다.

테스트를 날짜/시간 분리 구조와 현황 조회 모킹·대기에 맞게 수정했다. 30분 선택지49개·24:00의 다음 날 정규화·겹침/맞닿음·조회 중 차단·조회 실패 재시도·새 예약된 시간 선택 해제·늦은 이전 현황 무시와 API의 모든 페이지·빈 결과·잘못된 상태·마이크로초 종료 보정을 추가 검증했다. 애플리케이션 로직·CI·백엔드·의존성은 변경하지 않았다.

최초 수정 후 전체68개가 통과했다. 독립 리뷰의 Minor 보완 후 CI 순서인 npm run lint·npm run type-check·npm run test:unit·npm run build를 다시 실행해 모두 종료코드0, 전체69개 통과를 확인했다. 문서 링크·git diff --check·신규 파일 공백 검사도 통과했다.

Superpowers requesting-code-review의 독립 리뷰어 Subagent가 HEAD `bdb230b` 대비 테스트·문서 변경과 관련 UI/API 문맥을 검토했다. Critical 0·Important 0·Minor 1건(제목은 다른 공간/취소 응답을 말하지만 취소만 검증)을 확인해 it.each로 공간 ID 불일치 사례도 추가했다. 리뷰어는 테스트·빌드·브라우저를 재실행하지 않았다. 중요한 앱 로직 수정이 없어 중복 리뷰하지 않았다.

현재 결과는 모킹 기반 로컬 검증이며 수정본의 원격 CI·실제 브라우저·실제 API 재검증은 수행하지 않았다. 커밋·push는 하지 않았다. 기존 사전선택 GET/생성 POST의 늦은 응답 회귀 테스트 보강은 후속이며, 이번에는 예약 현황 GET의 늦은 응답 무시를 보강했다.
