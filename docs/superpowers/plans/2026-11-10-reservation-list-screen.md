# 예약 목록·취소 화면 계획

**Goal:** 공간·상태·조회 구간 필터·페이징과 서울 시각 표시, 취소 확인·오류·목록 갱신.

**Architecture:** /reservations, 기존 fetch·공간20개페이지·반응형 CSS 재사용. API의 Reservation을 두 상태로 확장하고 목록/취소 응답을 검증한다. 시간 입력은 기존 생성 화면과 같은 날짜+24시간30분 선택, 24:00은 다음날로 정규화하는 작은 공유 함수를 추출한다. 라이브러리·백엔드·CI 변경 없음.

**계약:** 선택 필터는 생략, from/to 동시 지정·겹침 조회·과거 허용, page0/size20·고정정렬. UI 초안과 적용 필터를 분리하고 적용/초기화는 page0. 공간 필터도 전체를 한 페이지로 가정하지 않는다. 표는 공간ID·링크를 사용하며 무한 N+1 이름 조회는 하지 않는다. 취소는 인라인 확인 후 명시적POST, 중복/자동재시도 없음. 성공 후 동일조건 갱신·빈 마지막페이지 보정. 취소 성공과 후속조회 실패는 구분. 404/409/503/통신 오류 안내. 시작/상태 UI판단은 보조이며 서버최종판정. 브라우저 이전미검증지시유지.
