# Swagger UI 구현 계획

**Goal:** 기존 API를 Swagger UI로 탐색하고 예시 요청을 실행한다.

**Architecture:** springdoc-openapi 2.10.0(공식 Boot 3.5 호환 계열)을 고정한다. 문서 전용 OpenApiCustomizer와 Clock으로 요청 예시를 구성하고 문서 캐시를 끈다. 비즈니스 로직과 DB는 변경하지 않는다.

**승인 계약:** 공간 예시, 문서 조회 시점의 미래 예약 예시, ID·필터 예시를 제공한다. 데이터 자동 삽입은 하지 않는다. 실제 ID 입력과 중복 실행 시 409를 안내한다. 정적 날짜는 만료되므로 채택하지 않았다. 별도 Swagger 프런트엔드 대신 starter 내장 UI를 사용한다.

## 작업

- [x] PostgreSQL HTTP 테스트로 UI·OpenAPI 경로, 파라미터 계약, 예시를 사용하는 공간→예약→조회→취소 흐름을 먼저 작성하고 실패를 확인한다.
- [x] 의존성, 문서 설정, 요청 예시와 오류 스키마를 추가하고 관련 테스트를 통과시킨다.
- [x] README·실행 안내·아키텍처·API 문서에 접근 방법과 예시의 한계를 기록한다.
- [x] 전체 clean build, diff 검사, 독립 리뷰를 수행하고 실제 결과를 기록한다. Important 1건은 재현·수정·전체 재검증과 수정 부분 재검토를 완료했다. 상세 결과는 [swagger.md](../../swagger.md)를 따른다.

## 검토 초점

예시는 실제 입력 검증을 통과해야 한다. 선택 필터는 기본값으로 바꾸지 않는다. 문서의 타입·상태·오류는 실제 계약과 일치해야 한다. 문서 갱신 시 시각이 재생성되어야 한다. 실제 ID나 공간 존재를 가정해 자동 생성하지 않는다.

커밋·push는 하지 않는다. 구현은 현재 세션에서 진행하고 최종 독립 리뷰를 수행한다.
