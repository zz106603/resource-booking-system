# 공간 등록·조회 API

## 범위와 구현 순서

[요구사항](requirements.md)의 F1·F2, AC1·AC2와 AC3의 공간 조회 부분을 구현한다. 예약과 프런트엔드는 포함하지 않는다.

1. 실제 PostgreSQL과 HTTP 요청을 사용하는 등록·조회·검증·오류 통합 테스트를 작성하고 미구현 실패를 확인한다.
2. Flyway V2로 spaces를 추가하고 space 패키지의 엔티티·저장소·서비스·API DTO를 구현한다.
3. 공통 오류 응답을 구성하고 빌드·테스트를 실행한다.
4. 실제 검증 결과와 미결정 사항을 문서에 갱신한다. 커밋·push는 하지 않는다.

## 이번 구현의 계약

| 요청 | 성공 응답 |
| --- | --- |
| `POST /api/spaces` | 201, `Location: /api/spaces/{id}`, 생성된 공간 |
| `GET /api/spaces/{id}` | 200, 공간 상세 |
| `GET /api/spaces?page=0&size=20` | 200, ID 오름차순 페이지 |

등록 요청: `name`은 공백만으로 구성할 수 없는 최대 100자 문자열, `description`은 선택 문자열(null 허용, 최대 2,000자), `capacity`는 필수 양의 32비트 정수다. 소수·숫자 문자열 입력과 숫자·불리언의 문자열 자동 변환은 거부한다. 이름 중복은 허용하며 입력 문자열은 그대로 보존한다.

상세·등록 응답은 `id`, `name`, `description`, `capacity`, `createdAt`을 반환한다. `createdAt`은 주입된 Clock으로 생성하고 PostgreSQL 정밀도에 맞춰 마이크로초로 정규화하는 UTC 시각이다. 목록은 `content`, `page`, `size`, `totalElements`, `totalPages`로 구성한다. 페이지는 0 이상, 크기는 1~100이며 기본값은 각각 0과 20이다. 빈 목록과 범위를 벗어난 페이지는 빈 content로 200을 반환한다. 클라이언트 정렬 옵션은 제공하지 않는다.

없는 양의 ID는 404, 양수가 아닌 ID·잘못된 형식·필드·페이지 입력은 400이다. 공통 오류는 `code`, `message`, `fieldErrors`(각 항목은 `field`, `message`)를 포함하며 내부 예외나 SQL·스택 추적은 노출하지 않는다.

| 오류 | HTTP 상태 | code |
| --- | --- | --- |
| 등록 필드의 필수값·범위·길이 검증 | 400 | `VALIDATION_ERROR` (fieldErrors 포함) |
| 잘못된 JSON·타입·ID·페이지 파라미터 | 400 | `INVALID_REQUEST` |
| 존재하지 않는 공간 | 404 | `SPACE_NOT_FOUND` |
| 예상하지 못한 내부 실패 | 500 | `INTERNAL_ERROR` |

등록 요청 예시:

```json
{"name":"회의실 A","description":"창문이 있는 회의실","capacity":6}
```

DB는 BIGINT IDENTITY 기본키, 필수값·양의 수용 인원·빈 이름 방지 제약을 사용한다. 초기 V1은 변경하지 않고 V2를 추가한다. 도메인 API 구현 시 필요한 길이 제한과 페이지 정책은 이번 구현의 기본값으로 정했으며, 예약 정책에는 적용하지 않는다.

## 실제 검증 결과 (2026-10-28)

`backend/`에서 실행:

```powershell
.\gradlew.bat clean build --no-daemon
```

최종 결과: **BUILD SUCCESSFUL**, 약 38초. 실행 JAR 빌드와 테스트 39개 통과, 실패·오류·건너뜀 모두 0.

- `SpaceApiIntegrationTest`: 실제 HTTP와 PostgreSQL 17.11로 37개 검증. 생성·저장·상세·목록·페이징·중복 이름·선택 설명·경계값·잘못된 입력·DB 제약·404·500 응답을 확인했다. DB 장애 테스트는 테스트 전용 컨테이너의 테이블 이름을 일시 변경하고 finally에서 복구한다.
- `PostgresIntegrationTest`: 기본 웹·DB·Flyway 기동과 별도 스키마에서의 V1→V2 업그레이드 2개 검증.
- 테스트용 애플리케이션은 종료되었고 PostgreSQL 컨테이너는 Testcontainers가 정리한다. Compose DB는 사용하지 않았다.
- 문서 참조 경로와 `git diff --check`, 미추적 신규 파일 공백 검사도 확인한다. 애플리케이션 빌드·테스트와 문서 검증은 구분한다.

### 실패와 수정

1. 미구현 상태에서 공간 테스트 34개가 `spaces` 테이블 부재로 실패했다. V2와 API를 추가해 진행했다.
2. 첫 전체 빌드는 테스트 35개 중 1개가 실패했다. 생성 응답의 나노초 시각과 PostgreSQL 재조회 시 마이크로초 반올림 결과가 달랐다. 주입된 Clock의 시각을 저장 전에 마이크로초로 정규화했고 생성·상세 응답 일치 테스트로 검증했다.
3. 잘못된 JSON 타입 테스트 10개 중 추가한 3개가 실패했다. Jackson이 숫자 이름·설명과 숫자 문자열 수용 인원을 자동 변환하고 있었다. 명시적인 타입 변환 거부 설정을 추가했고 최종 전체 테스트에서 모두 통과했다.
4. 기본 권한의 Docker 조회는 접근 거부였으며, Docker 접근이 허용된 실행에서 엔진 연결과 테스트를 수행했다. 테스트 JVM의 클래스 공유 경고는 있었으나 최종 테스트 실패는 없었다. 의도적인 DB 장애 테스트에서의 서버 오류 로그는 예상된 검증 과정이다.

## 남은 작업

이번 공간 API 계약은 구현 기본값으로 구체화했다. 예약 정책·예약 API·동시성 제어·인증·프런트엔드·CI는 이번 작업에 포함하지 않는다. 예약 구현 전에는 기존 문서의 미결정 사항과 잠금 대안을 별도로 확인한다.
